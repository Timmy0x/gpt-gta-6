Camera query storage checkpoint, based on pushed `b0bb9b7`. Owned runtime change: `src/core/CameraMeshQueries.ts`. Player, CameraOcclusion, provider transport/render streaming, source placement and physics assets remain outside this change.

The camera now reads existing native position storage through three scratch vectors. It does not call `_generatePointsArray()` for eligible triangle meshes, copy/deinterleave source buffers, or make detached native SubMesh objects. Cache entries contain scalar partition bounds/index ranges, existing position/index storage references and original render SubMesh references, with the existing 128-mesh/8192-part cap. Mutable position/index buffers build fresh transient scalar ranges each query; immutable entries validate buffer/data/index identities and submesh/material ranges. Disabled/disposed mesh entries and scene disposal release cache references. Source storage stays presentation-only and in memory; nothing is exported or converted to physical geometry.

Native `Ray.TransformToRef` preserves transformed finite length and epsilon. Native `Ray.intersectsTriangle` preserves two-sided closest hits; the closest local hit is transformed back to world distance. Position reading supports packed and interleaved FLOAT storage, byte offsets into ArrayBuffer views, number arrays, normalized integer formats and HALF_FLOAT. Quantized/interleaved values match native `getFloatData` Float32 conversion without allocating packed copies. Exact near-camera triangle/box clearance still tests source triangles, including small blockers between finite boom rays. Original render submeshes/materials/buffers remain intact.
