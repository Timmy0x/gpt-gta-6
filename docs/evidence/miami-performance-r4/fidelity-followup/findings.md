# Read-only R4 source fidelity follow-up

The next justified experiment is a controlled decrease of the renderer's screen-space error target. This may select finer available source tiles at street level; it is not proof that the current trees/roads are coarse because of LOD, nor a promise of photorealism, source recency or exact whole-Miami parity. No frozen R4 runtime, quality setting, camera, token or live provider session was changed or accessed for this review.

## What the pinned implementation establishes

- `StreamedMiamiVisuals.ts:56` fixes `errorTarget=20`, four downloads per origin and two parse jobs. The visual LRU is 960 admitted items / 640 minimum. `loadAncestors=true` retains coarse fallbacks while detail loads. Although `loadSiblings=false` is assigned, pinned core traversal treats sibling loading as enabled when ancestors are enabled. Increasing siblings is therefore not a useful independent experiment here.
- Core 0.5.2 `canTraverse` stops a conditional branch when its calculated error is at or below `errorTarget`; its default target is 16. A reduction from 20 to 16, then 12 or 8 in a separate candidate, can cause traversal to descend further where finer children exist and are loadable. This is an inference from the local algorithm, not a result from observed Miami content.
- The LH adapter measures actual framebuffer pixels times the active camera viewport. Perspective error is `geometricError * errorScale * framebufferHeight * viewportHeight * abs(projection[5]) / (2 * distance)`. Orthographic error uses the larger world-metres-per-framebuffer-pixel dimension. No extra hardware-scaling multiplier belongs in these formulas. The game's low/medium/high settings use hardware scale 1.7/1.3/1, so framebuffer size must be held constant to isolate an LOD change; higher rendering resolution already increases computed SSE and may cause more refinement.
- `LocalTileBounds` composes source transforms in doubles, calculates distances to a stable oriented enclosure, and conservatively handles rounded/sheared/degenerate boxes and transformed spheres. Frustum decisions use original transformed corners or spheres. The former loose AABB-distance defect is already fixed; deliberately making distances smaller is not an appropriate fidelity fix. Regional/sheared bounds can remain conservative, so this is not an exact per-triangle source error measurement. Bounds influence tile selection, not source texture/detail generation.
- The R4 cache preserves those same errors and decisions exactly. Lowering the threshold is a distinct quality change; the cache alone should not alter the image.
- Current byte limits use the backend's estimate of one byte per tile. They are tracker safeguards, not measured RAM/VRAM budgets. Passive resource estimates and stream status can show admission saturation, unknown resources, pending work and load/parse failures. A lower threshold can increase requests, geometry, textures, first-use camera query work and transitions; a full protected cache or failed child can continue displaying ancestors.

Google's official overview describes 3D geodata served in OGC 3D Tiles and updates to coverage; it does not certify these particular Miami street-level surfaces or their capture date. Request URLs follow child tileset URIs plus session/auth parameters, and the renderer must retain Google branding and tile-dependent attribution. An experiment can use the existing live visualization path without copying provider meshes, textures or derived collision data. [Official overview](https://developers.google.com/maps/documentation/tile/3d-tiles-overview), [official renderer guidance](https://developers.google.com/maps/documentation/tile/create-renderer) (checked 2026-09-29).

If a tree canopy or road edge is merged, blurry or inaccurate in the finest available source, a lower SSE target cannot reconstruct missing geometry, remove baked source artifacts or produce independently damageable objects. These are limits of the inference from selecting more detail; the present review has not inspected or certified the provider's finest Miami leaves. Independent, licensed gameplay assets and physical sources remain separate work.

## Controlled future experiment

1. Create a separate candidate with one numeric, validated test-only LOD setting. Keep the accepted R4 default at 20 until evaluation. Test 20 versus 16 first; only proceed to 12 and 8 if finer source content appears and performance/resources stay acceptable. Hold framebuffer dimensions, camera FOV/viewport, backend, scene time/weather, actor density, source origin and all loading/cache safeguards fixed. Do not simultaneously raise the tile cap, change queue concurrency or alter collision readiness.
2. Native gate: use the actual pinned importer and original synthetic multilevel hierarchy with known errors/distances. Sweep perspective/orthographic views and viewport/framebuffer changes; verify exact SSE arithmetic, controlled threshold crossings, progressively finer visible frontiers when capacity is sufficient, parent fallback during delayed children, hide/restore credits, bounded count under a deliberately small cache, failures/cancellation/reconnect and unchanged collision/travel safeguards. Include the tilted slab, transformed/sheared box and zero-distance cases. Synthetic loading counts and CPU timings must stay labeled synthetic, not live FPS or source fidelity.
3. Browser A/B: use normal named travel and input at at least three supported locations: a close Brickell curb/tree/façade view, a distant street view and an outlying street with traffic. Match pose and framebuffer, inspect initial loading separately, then wait for queues and model loads to settle or a documented bounded timeout. Compare the same rendered views at 20/16, including camera turns and a short repeated walking/driving route. Retain ordinary rendered screenshots and sanitized numeric summaries only; no tile payloads, source buffers, credentials, provider URLs or geometry exports.
4. Measure each setting in a fresh labeled run so the performance report cannot mix earlier quality settings. Capture at least 180 seconds of comparable active play after the documented warmup; repeat in alternating A/B order three times per backend. Keep stalls and visual/collision holds in raw frame measurements. Report median frame time/FPS, the report's defined 1% low, maxima, frames over 33/100 ms, cold-load/settle time, numeric requests/model loads/disposals, cache admission/protected-used counts, pending/error counts and passive buffer/texture estimates with unknowns. JS heap, buffer estimates, GPU time and process memory are different quantities; do not treat one as another.
5. Diagnose before escalating: if the image gets sharper and loading/resource costs are acceptable, the lower target is a candidate improvement. If queues remain pending or cache admission is saturated, determine that cause before increasing limits. If visible detail is unchanged once the requested frontier has settled, or the finest available children still show merged/blurry surfaces, record that source limitation and stop reducing the target. Preserve required branding/credits in all views and leave independent physical collision/support intact.

Success means a visible, reproducible improvement at the tested views within the existing resource/readiness constraints. It does not establish whole-city coverage, centimetre survey accuracy, contemporary buildings, complete interiors, independently interactive trees or the user's final visual acceptance.
