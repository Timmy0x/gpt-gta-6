# Miami source detail and bounded native work

R5 follows accepted `9cf3af6`. Map detail is separate from display resolution: Pause → Map detail chooses Balanced (20 framebuffer-pixel error), High (12) or Ultra (8). The default remains Balanced pending retained live comparisons. The selected detail profile joins existing sandbox save/load settings; only that enum is persisted, never credentials. Changing detail adjusts the existing scene-owned renderer without reconnecting the credential, replacing the camera or changing collision quality. The same source coverage, credit rules, resident limits and concurrent jobs apply. This requests finer available source tiles; it cannot repair detail absent from captured data.

Pause → Export performance includes raw frame durations plus CPU-stage summaries from Babylon's native SceneInstrumentation and measured application stages. All native fixed substeps in a rendered interval are summed. A held frame contributes zero physics work. Application measurements cover public collision maintenance, player camera/pose and source tile traversal. Scene CPU contains several of these stages, so they must not be added together. GPU work, asynchronous callbacks and waiting between frames are outside stage measurements; their stalls still affect raw frame durations. Raw durations measure elapsed time since the preceding render-loop callback, while CPU stages describe the just-rendered frame, so individual records are not exact timestamp-aligned attribution. No FPS acceptance is inferred from CPU counters.

Restart sample explicitly clears both frame and CPU histories and resumes play. Settings and resolution in an exported report describe export time; a sample with changing settings must be interpreted accordingly. The reset does not clear injuries, traffic, damage, credentials or the world. Each bounded history holds at most 108000 sampled active frames. Six CPU histories require about 5.2MB of typed storage, separate from the existing raw frame history and all native/GPU resources.

The exact integrated runtime passed all 401 native tests and production build. Actual pinned renderer checks include failed-child fallback, 960-item resident limits and update callbacks that reenter, throw, disconnect or replace the owner. The normal local WebGL2 UI verified connection, High → save → Ultra → load restoring High, a visible Ultra frontier, report restart and matching raw/CPU sample counts. Evidence is under `docs/evidence/miami-fidelity-r5`. The 1280×720 local view still shows distorted captured trees, cars and pavement; these UI checks do not establish visual parity or a performance target. Collision preparation scheduling is a separate pending checkpoint. Exact whole-Miami appearance, every physical object, current source/physical surface correspondence and the 1080p 30-minute performance target remain incomplete. Source acquisition north of Brickell is preparatory until compiled and independently tested travel actually becomes available.

CPU category boundaries: collisionStreaming also includes anchor maintenance and the entire world.update call, including ocean/street-object maintenance. physicsCpu covers Babylon’s native physics timing window; later boundary enforcement and interpolation callbacks are outside that counter. The stage names do not imply complete subsystem attribution.
