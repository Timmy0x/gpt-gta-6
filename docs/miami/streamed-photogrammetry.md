# Streamed photogrammetry source investigation

Reviewed 12 September 2026. The user requires parity of every Miami building, street and elevation. The currently imported County2015 volumes do not establish this. A regional map visualization and a fully interactive, destructible game map have different data requirements; neither current source coverage nor visual fidelity is accepted.

Latest steering: after selecting Aerometrex and confirming no delivery link, the user asked why Google Earth or Apple Maps could not be used. No Aerometrex request has been sent. Google is a viable streamed visual source to evaluate; the consumer Google Earth app is not the integration API. Apple’s documented [MapKit JS API](https://developer.apple.com/documentation/mapkitjs/) supplies embedded maps, place details and Look Around imagery, with no documented city-mesh feed for this Babylon game.

Google Photorealistic3D Tiles is an actual imagery-textured3D mesh service. It supports compatible OGC3D Tiles renderers. Access needs a billing-enabled Google Cloud project, Map Tiles API and restricted API key. One root request supports at least three hours of tile requests. [Official access documentation](https://developers.google.com/maps/documentation/tile/3d-tiles).

The standard service is for visualization. Its policy disallows extraction and unrestricted storage/offline use, requires Google and per-tile provider attribution, and says overlaid models cannot be traced or derived from the tiles. Thus it is a candidate for a separately attributed live geographic view, not an accepted source for copying permanent destructible assets. No source tiles have been scraped or extracted. [Map Tiles policy](https://developers.google.com/maps/documentation/tile/policies).

Google describes regularly updated global urban coverage; that alone does not certify every Miami street, current building, surveyed elevation, facade or interior. A coverage inspection at the exact Brickell coordinates and several ground-level views is still needed. Photogrammetry should be checked for occlusion, merged trees/cars, blurred facades, baked lighting and surface holes before proposing gameplay use. These are evaluation criteria, not observations from a loaded Miami tileset. [Overview](https://developers.google.com/maps/documentation/tile/3d-tiles-overview).

Cesium provides supported browser, Unity and Unreal integrations and offers Google tiles through Cesium ion accounts. That is an alternate service integration path; it does not turn streamed content into an unrestricted downloadable asset. No account has been created or charge authorized. [Cesium integration](https://cesium.com/learn/photorealistic-3d-tiles-learn/), [CesiumJS tutorial](https://cesium.com/learn/cesiumjs-learn/cesiumjs-photorealistic-3d-tiles/).

The [official Babylon guide](https://github.com/BabylonJS/Documentation/blob/master/content/features/featuresDeepDive/geospatial/loading3dTiles.md) now recommends NASA/AMMOS `3d-tiles-renderer/babylonjs`, with a [Google demonstration](https://demos.babylonjs.com/3d-tiles/). Its [current renderer limitations](https://github.com/NASA-AMMOS/3DTilesRendererJS/blob/master/src/babylonjs/renderer/README.md) include a right-handed scene requirement, no boundingRegion support, and no I3DM/PNTS. Our game is left-handed, so changing a URL is insufficient: the integration must handle shared coordinates, camera/depth, streaming and collision readiness without reversing existing gameplay. An isolated streamed-source preview is in preparation; no Google or Cesium credentials have been acquired.

Google's direct API rejects Photorealistic 3D Tiles for new EEA-billed projects under its [EEA changes](https://developers.google.com/maps/comms/eea/map-tiles). User location/timezone does not establish billing-country eligibility. Cesium offers its own documented account route, but no official confirmation was found that this resolves any particular user's EEA eligibility; do not claim it bypasses the restriction.

Current repository has no configured Google/Cesium credential file. Do not expose a secret in source or commit an unrestricted browser key. Before requesting user setup, build a concrete reference-view integration, verify the selected provider's Miami coverage/demo, and present current price/quota and usage scope. Keep the native game map work progressing from licensed authoritative survey sources in parallel. Do not claim that any one source guarantees perfect contemporary parity.
